
## Теория

### Что такое реестр Windows

Реестр Windows это системная база данных, в которой Windows и приложения хранят параметры конфигурации.

Например, приложение может хранить:
- выбранную тему оформления;
- путь к последнему открытому файлу;
- количество запусков;
- пользовательские настройки интерфейса.

Реестр не предназначен для хранения больших файлов, изображений или произвольных объёмов данных. Для этого подходят файлы, базы данных и другие хранилища.

#### что произойдёт, если приложение будет сохранять настройки только в переменных?
```spoiler
после закрытия приложения значения из памяти исчезнут.
```
### Ключи и значения

Реестр имеет древовидную структуру.
- Ключ (Key) - контейнер, в котором находятся другие ключи и значения.
- Значение (Value) - конкретный параметр с именем, типом и данными.

Пример нашей ветки:

```
HKEY_CURRENT_USER
└── Software
    └── StudentSystemProgramming
        ├── Theme          = "Dark"
        ├── LaunchCount    = 5
        └── SchemaVersion  = 1
```

В этом примере:
- `StudentSystemProgramming` - ключ;
- `Theme` - строковое значение;
- `LaunchCount` - числовое значение;
- `SchemaVersion` - версия структуры настроек.

Что произойдёт, если попытаться прочитать несуществующее значение?

Приложение должно получить предусмотренное значение по умолчанию, а не завершиться с ошибкой.

### HKCU и HKLM

В реестре есть несколько основных корневых веток. Для занятия достаточно двух.

| Ветка                       | Назначение                         |
| --------------------------- | ---------------------------------- |
| `HKEY_CURRENT_USER (HKCU)`  | Настройки текущего пользователя    |
| `HKEY_LOCAL_MACHINE (HKLM)` | Общесистемные настройки компьютера |

HKCU подходит для настроек, которые относятся к конкретному пользователю.
HKLM используется для системных и общих настроек. Изменение этой ветки часто требует повышенных прав.

В нашем проекте используется только `HKCU`.

### Работа с реестром из C#

```cs
// Основной API находится в пространстве имён:
using Microsoft.Win32;

// Для доступа к пользовательской ветке используется:
Registry.CurrentUser

// Создание или открытие ключа
// `CreateSubKey` создаёт ключ, если его нет, и открывает его, если он уже существует.
// `OpenSubKey` только открывает существующий ключ.
using RegistryKey key =
    Registry.CurrentUser.CreateSubKey(
        @"Software\StudentSystemProgramming",
        writable: true);

// Запись
key.SetValue("Theme", "Dark", RegistryValueKind.String);

key.SetValue("LaunchCount", 5, RegistryValueKind.DWord);

// Чтение
string theme = key.GetValue(
    "Theme",
    "Light")?.ToString() ?? "Light";

int launchCount = Convert.ToInt32(
    key.GetValue("LaunchCount", 0));
```

Типы значений, которые важно знать:

| Тип      | Назначение            |
| -------- | --------------------- |
| `String` | Строка                |
| `DWord`  | 32-битное целое число |
| `QWord`  | 64-битное целое число |
| `Binary` | Бинарные данные       |
### Права доступа и безопасность

Реестр - не обычная переменная приложения. Операции с ним могут завершиться ошибкой из-за прав доступа.

```cs
// Основное исключение
UnauthorizedAccessException
```

Оно может возникнуть, если приложение пытается изменить ключ, на который у него нет прав.

Также возможны:
- `SecurityException` - операция запрещена политикой безопасности;
- `IOException` - ошибка операции с реестром.

Правило занятия: приложение изменяет только собственную ветку в `HKCU`.

Нельзя:
- удалять целиком `HKCU\Software`;
- изменять чужие ветки;
- использовать `HKLM` только ради того, чтобы «настройки были надёжнее»;
- скрывать ошибки пустым `catch`.

### Значения по умолчанию

При первом запуске ключа может ещё не существовать. Это нормальная ситуация.

Поэтому приложение должно иметь значения по умолчанию:

```cs
string theme = "Light";
int launchCount = 0;
```

Дальше оно:
1. пытается прочитать настройки;
2. если их нет - использует значения по умолчанию;
3. сохраняет полученные настройки;
4. продолжает запуск.

#### почему отсутствие настройки - не обязательно ошибка?
```spoiler
Потому что приложение может запускаться впервые, а настройки ещё не были созданы.
```

### `RegistrySettingsService.cs`
```cs

using Microsoft.Win32;
using StudentSystemProgramming.Models;

namespace StudentSystemProgramming.Services;

public sealed class RegistrySettingsService
{
    private const string RegistryPath =
        @"Software\StudentSystemProgramming";

    public AppSettings Load()
    {
        var settings = new AppSettings();

		// Открытие ключа
		// OpenSubKey возвращает `null`, если ключ отсутствует
		// Это не исключительная ситуация, потому что приложение может быть запущено впервые
		// Почему используется `using`? 
		// `RegistryKey` реализует `IDisposable`. После работы с ключом его необходимо освободить.
        using RegistryKey? key =
            Registry.CurrentUser.OpenSubKey(RegistryPath);

        // Если ключа нет, возвращаем настройки по умолчанию.
        if (key is null)
        {
            return settings;
        }

		// Чтение значения
		// `GetValue` возвращает `object?`, потому что в реестре могут храниться разные типы данных
		// Поэтому мы проверяем тип через `is string` чуть далее
        object? themeValue = key.GetValue("Theme");
        object? launchCountValue = key.GetValue("LaunchCount");
        

        if (themeValue is string theme &&
            (theme == "Light" || theme == "Dark"))
        {
            settings.Theme = theme;
        }

        if (launchCountValue is int launchCount &&
            launchCount >= 0)
        {
            settings.LaunchCount = launchCount;
        }

        return settings;
    }

    public void Save(AppSettings settings)
    {
        ArgumentNullException.ThrowIfNull(settings);

        using RegistryKey key =
            Registry.CurrentUser.CreateSubKey(
                RegistryPath,
                writable: true);

        if (settings.Theme != "Light" &&
            settings.Theme != "Dark")
        {
            throw new ArgumentException(
                "Недопустимая тема оформления.");
        }

        if (settings.LaunchCount < 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(settings.LaunchCount));
        }
		// Сохранение
		// Третий параметр явно указывает тип значения
        key.SetValue(
            "Theme",
            settings.Theme,
            RegistryValueKind.String);

        key.SetValue(
            "LaunchCount",
            settings.LaunchCount,
            RegistryValueKind.DWord);
    }
}
```

## П2

Расширить приложение двумя возможностями:
1. Добавить `SchemaVersion` - версию структуры настроек.
2. Добавить команду `--reset`, которая удаляет только ветку `StudentSystemProgramming`.

Дополнительно нужно сохранить работоспособность старых настроек: если в реестре уже есть `Theme` и `LaunchCount`, но ещё нет `SchemaVersion`, приложение должно прочитать их и записать актуальную версию схемы.

### Зачем нужна версия схемы

Представим, что сегодня приложение хранит:
```
Theme
LaunchCount
```

А через месяц разработчик добавит:
```
Theme
LaunchCount
LastRunUtc
WindowWidth
WindowHeight
```

Структура настроек изменилась. Приложение должно понимать, с какой версией настроек оно работает.

Для этого добавляется:
```
SchemaVersion = 1
```

В дальнейшем, когда структура изменится, можно будет написать миграцию с версии 1 на версию 2.
Важно: версия схемы  это не версия сборки приложения. Она обозначает именно формат хранящихся настроек.

### `RegistrySettingsService.cs`
```cs

using Microsoft.Win32;
using StudentSystemProgramming.Models;

namespace StudentSystemProgramming.Services;
// Полностью заменить
// - если ключ отсутствует - возвращаются настройки по умолчанию;
// - если `SchemaVersion` отсутствует - считается, что это старая схема версии 0;
// - настройки старой схемы сохраняются, а версия обновляется до 1;
// - если версия выше поддерживаемой - приложение сообщает об этом;
// - сброс удаляет только учебную ветку.
public sealed class RegistrySettingsService
{
    private const string RegistryPath =
        @"Software\StudentSystemProgramming";

    private const int CurrentSchemaVersion = 1;

    public AppSettings Load()
    {
        var settings = new AppSettings();

        using RegistryKey? key =
            Registry.CurrentUser.OpenSubKey(RegistryPath);

        if (key is null)
        {
            return settings;
        }

        object? schemaValue = key.GetValue("SchemaVersion");

        int storedSchemaVersion = 0;

        if (schemaValue is int version)
        {
            storedSchemaVersion = version;
        }
        else if (schemaValue is not null)
        {
            throw new InvalidDataException(
                "Некорректный тип SchemaVersion в реестре.");
        }

        if (storedSchemaVersion < 0)
        {
            throw new InvalidDataException(
                "Версия схемы не может быть отрицательной.");
        }

        if (storedSchemaVersion > CurrentSchemaVersion)
        {
            throw new InvalidDataException(
                "Настройки созданы более новой версией приложения.");
        }

        object? themeValue = key.GetValue("Theme");
        object? launchCountValue = key.GetValue("LaunchCount");

        if (themeValue is string theme &&
            (theme == "Light" || theme == "Dark"))
        {
            settings.Theme = theme;
        }

        if (launchCountValue is int launchCount &&
            launchCount >= 0)
        {
            settings.LaunchCount = launchCount;
        }

        // Версия 0 означает старую схему без SchemaVersion.
        // После чтения известных значений сохраняем актуальную версию.
        if (storedSchemaVersion < CurrentSchemaVersion)
        {
            Save(settings);
        }

        return settings;
    }

    public void Save(AppSettings settings)
    {
        ArgumentNullException.ThrowIfNull(settings);

        if (settings.Theme != "Light" &&
            settings.Theme != "Dark")
        {
            throw new ArgumentException(
                "Недопустимая тема оформления.");
        }

        if (settings.LaunchCount < 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(settings.LaunchCount));
        }

        using RegistryKey key =
            Registry.CurrentUser.CreateSubKey(
                RegistryPath,
                writable: true);

        key.SetValue(
            "Theme",
            settings.Theme,
            RegistryValueKind.String);

        key.SetValue(
            "LaunchCount",
            settings.LaunchCount,
            RegistryValueKind.DWord);

        key.SetValue(
            "SchemaVersion",
            CurrentSchemaVersion,
            RegistryValueKind.DWord);
    }

	// Удаляется только HKCU\Software\StudentSystemProgramming
	// Не удаляется родительский ключ `Software` и тем более вся ветка `HKCU`
	// `throwOnMissingSubKey: false` означает, что отсутствие удаляемого ключа не считается ошибкой.
    public void Reset()
    {
        Registry.CurrentUser.DeleteSubKeyTree(
            RegistryPath,
            throwOnMissingSubKey: false);
    }
}
```

### `Program.cs`
```cs
using StudentSystemProgramming.Models;
using StudentSystemProgramming.Services;

var service = new RegistrySettingsService();

// Теперь приложение поддерживает два режима:
// - обычный запуск - загрузить настройки, увеличить счётчик, сохранить;
// - запуск с аргументом `--reset` - удалить учебную ветку.
try
{
    // Отдельный режим сброса настроек.
    if (args.Length > 0 && args[0] == "--reset")
    {
        service.Reset();

        Console.WriteLine("Учебные настройки сброшены.");
        return;
    }

    AppSettings settings = service.Load();

    Console.WriteLine("Настройки приложения");
    Console.WriteLine("--------------------");
    Console.WriteLine($"Тема: {settings.Theme}");
    Console.WriteLine($"Запусков: {settings.LaunchCount}");
    Console.WriteLine($"Версия схемы: {settings.SchemaVersion}");

    Console.WriteLine();
    Console.WriteLine("Выберите тему:");
    Console.WriteLine("1 - Light");
    Console.WriteLine("2 - Dark");
    Console.WriteLine("Enter - оставить текущую");

    string? choice = Console.ReadLine();

    if (choice == "1")
        settings.Theme = "Light";
    else if (choice == "2")
        settings.Theme = "Dark";

    // checked не позволяет незаметно переполнить int.
    settings.LaunchCount = checked(settings.LaunchCount + 1);

    service.Save(settings);

    Console.WriteLine();
    Console.WriteLine("Настройки сохранены.");
    Console.WriteLine($"Тема: {settings.Theme}");

}

## Проверка результата

### Ожидаемая структура реестра

После нескольких запусков приложения:

```
HKEY_CURRENT_USER
└── Software
    └── StudentSystemProgramming
        ├── Theme          REG_SZ       Dark
        ├── LaunchCount    REG_DWORD    3
        └── SchemaVersion REG_DWORD    1
```

### Контрольные сценарии

|Сценарий|Ожидаемое поведение|
|---|---|
|Ключ отсутствует|Настройки по умолчанию|
|Отсутствует `Theme`|Используется `Light`|
|Отсутствует `LaunchCount`|Используется `0`|
|`Theme` содержит `Blue`|Используется `Light`|
|`SchemaVersion` отсутствует|Выполняется переход со старой схемы|
|`SchemaVersion = 99`|Сообщение о неподдерживаемой версии|
|Выполнен `--reset`|Удалена только учебная ветка|
|Нет прав на изменение ключа|Выводится понятная ошибка|

### Типичные возможные ошибки 

|Ошибка|Почему это проблема|Исправление|
|---|---|---|
|Использовать `HKLM` для пользовательских настроек|Необоснованные требования к правам|Использовать `HKCU`|
|Вызывать только `OpenSubKey` при первом запуске|Ключа может не существовать|Обработать `null`|
|Не проверять тип значения|В реестре может оказаться значение неожиданного типа|Проверять через `is`|
|Удалять `HKCU\Software` целиком|Можно повредить настройки других приложений|Удалять только собственную ветку|
|Не освобождать `RegistryKey`|Дескрипторы могут оставаться открытыми|Использовать `using`|
|Использовать пустой `catch`|Ошибка скрывается от пользователя и разработчика|Обрабатывать ожидаемые исключения|

## Ограничения выбранного решения

Важно, чтобы вы понимали: реестр подходит не для всех настроек.

Подходит для:
- небольшого количества пользовательских параметров;
- настроек запуска приложения;
- параметров интерфейса;
- простых пользовательских предпочтений.

Не подходит для:

- больших объёмов данных;
- истории действий;
- сложных структур и коллекций;
- хранения паролей и секретов в открытом виде;
- совместного хранения больших объёмов данных несколькими приложениями.

Также `HKCU` относится к текущему пользователю Windows. Если другой пользователь войдёт в систему, он будет работать со своей пользовательской веткой реестра.
Отдельно стоит отметить: настройки в реестре не являются защищённым хранилищем. Пользователь или другая программа с соответствующими правами могут их изменить. Поэтому приложению нужно проверять загруженные значения, а не безусловно доверять им.

    out lastRun);
```

Если значения нет или дата имеет некорректный формат, приложение должно корректно сообщить, что предыдущий запуск неизвестен.

Что необходимо сделать:
1. Добавить `LastRunUtc` в `AppSettings`.
2. Научить `RegistrySettingsService` читать и сохранять значение.
3. Проверить поведение при первом запуске.
4. Удалить `LastRunUtc` вручную через `regedit` и проверить повторный запуск.
5. Записать некорректную дату и проверить обработку.
6. Объяснить, почему используется UTC, а не локальное время.
