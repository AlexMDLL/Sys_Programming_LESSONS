
Занятие логично продолжает тему `Task`, потоков и синхронизации, но теперь акцент смещается с управления задачами на ускорение вычислений за счёт параллельного выполнения.

Главная практическая идея: получаем один и тот же массив данных, реализуют два способа обработки — последовательный и параллельный, проверяют совпадение результатов и экспериментально выясняют, когда параллельный вариант действительно быстрее.
## Теория

### Конкурентность и параллелизм

Конкурентность (Concurrency) - организация выполнения нескольких задач так, чтобы их работа могла чередоваться или перекрываться во времени.
Параллелизм (Parallelism) - фактическое выполнение нескольких частей работы одновременно, например на разных ядрах процессора.

Пример:
- Конкурентность: программа одновременно обслуживает несколько запросов, переключаясь между ними во время ожидания.
- Параллелизм: программа одновременно вычисляет разные части массива на нескольких ядрах CPU.

```cs
// Конкурентность: задачи могут чередоваться.
Task task1 = DownloadDataAsync();
Task task2 = ReadFileAsync();

await Task.WhenAll(task1, task2);

// Параллелизм: итерации вычислительного цикла
// могут выполняться одновременно.
Parallel.For(0, 100, i =>
{
    Calculate(i);
});
```

#### Что произойдёт, если запустить десять CPU-bound задач на компьютере с двумя логическими процессорами?
```spoiler
Задачи смогут конкурировать за процессорное время, но одновременно исполняться на процессоре смогут не все десять. Само увеличение количества задач не гарантирует ускорения.
```
### `Parallel.For` и `Parallel.ForEach`

Оба метода находятся в пространстве имён `System.Threading.Tasks`.

```cs
// выполняет итерации цикла параллельно.
Parallel.For(0, 5, i =>
{
    Console.WriteLine($"Итерация {i}");
});

int[] numbers = { 10, 20, 30, 40, 50 };
// параллельно обрабатывает элементы коллекции или последовательности.
Parallel.ForEach(numbers, number =>
{
    Console.WriteLine(number * 2);
});
```

Важные особенности:
- Порядок выполнения итераций не гарантируется.
- Количество используемых потоков не гарантируется.
- Одна итерация не обязательно соответствует одному отдельному потоку.
- Итерации могут выполняться на нескольких потоках, а могут частично выполняться последовательно.

#### Если в `Parallel.For` указать диапазон от 0 до 1000, сколько потоков будет создано?
```spoiler
нельзя считать, что будет создано ровно 1000 потоков. Планировщик распределяет итерации с учётом доступных ресурсов и настроек параллелизма.
```
### Накладные расходы

Параллельное выполнение не бесплатно.
К накладным расходам относятся:
- распределение работы между потоками;
- планирование и переключение выполнения;
- синхронизация;
- объединение частичных результатов;
- конкуренция за память и кэш процессора.

Рассмотрим два варианта:
```cs
// Последовательно
for (int i = 0; i < 10; i++)
{
    result += i;
}

// Параллельно
Parallel.For(0, 10, i =>
{
    // Здесь ещё потребуется безопасно собрать результат.
});
```

Для десяти простых операций параллельный вариант может оказаться медленнее последовательного.

#### Что произойдёт, если распараллелить цикл, который выполняет всего десять сложений?
```spoiler
расходы на организацию параллельной работы могут превысить выигрыш от вычислений.
```
### `Stopwatch` и повторные измерения

`Stopwatch` из `System.Diagnostics` позволяет измерять время выполнения участка программы.
```cs
using System.Diagnostics;

var stopwatch = Stopwatch.StartNew();

long result = 0;

for (int i = 0; i < 1_000_000; i++)
{
    result += i;
}

stopwatch.Stop();

Console.WriteLine($"Результат: {result}");
Console.WriteLine($"Время: {stopwatch.ElapsedMilliseconds} мс");
```

Однако одного измерения недостаточно.

На время могут влиять:
- прогрев JIT-компилятора;
- нагрузка на компьютер;
- работа фоновых процессов;
- состояние кэшей процессора;

Поэтому нужно:
1. Выполнить прогрев.
2. Провести несколько измерений.
3. Сравнивать результаты одинаковых вычислений.
4. Использовать одинаковые входные данные.
5. Сравнивать не только время, но и корректность результата.

В этом занятии будем использовать пять измерений и медиану. Медиана меньше зависит от случайного единичного выброса, чем среднее арифметическое.

#### Если параллельный вариант один раз оказался быстрее, можно ли утверждать на основании одного измерения, что он всегда быстрее?
```spoiler
нет. Нужно провести серию измерений и проверить результаты на нескольких размерах данных.
```

### Что такое `MaxDegreeOfParallelism`

Это ограничение на максимальное количество одновременно выполняемых операций в параллельном цикле.
```cs
var options = new ParallelOptions
{
    MaxDegreeOfParallelism = 2
};

Parallel.For(0, 100, options, i =>
{
    Calculate(i);
});
```

Нужно проверить четыре варианта:
- `1` — ограничить параллельное выполнение одной операцией;
- `2` — не более двух одновременно выполняемых операций;
- `4` — не более четырёх;
- `-1` — использовать значение по умолчанию, без явного ограничения.

Обратите внимание: `MaxDegreeOfParallelism = 1` — это не то же самое, что обычный последовательный `foreach`. Это всё ещё вызов параллельного API с ограничением степени параллелизма.

### Calculator.cs`
```cs
namespace ParallelComputingLab;

public static class Calculator
{
    public static CalculationResult CalculateSequential(int[] numbers)
    {
        ArgumentNullException.ThrowIfNull(numbers);

        long sum = 0;
        int count = 0;

        foreach (int number in numbers)
        {
            if (number % 7 == 0)
            {
                sum += number;
                count++;
            }
        }

        return new CalculationResult(sum, count);
    }

    public static CalculationResult CalculateParallel(
        int[] numbers,
        int maxDegreeOfParallelism = -1)
    {
        ArgumentNullException.ThrowIfNull(numbers);

        if (maxDegreeOfParallelism != -1 &&
            maxDegreeOfParallelism < 1)
        {
            throw new ArgumentOutOfRangeException(
                nameof(maxDegreeOfParallelism));
        }

        long sum = 0;
        int count = 0;

        var options = new ParallelOptions
        {
            MaxDegreeOfParallelism = maxDegreeOfParallelism
        };

        Parallel.For(
            0,
            numbers.Length,
            options,
            () => (LocalSum: 0L, LocalCount: 0),
            (i, state, local) =>
            {
                int number = numbers[i];

                if (number % 7 == 0)
                {
                    local.LocalSum += number;
                    local.LocalCount++;
                }

                return local;
            },
            local =>
            {
                Interlocked.Add(ref sum, local.LocalSum);
                Interlocked.Add(ref count, local.LocalCount);
            });

        return new CalculationResult(sum, count);
    }
}
```

Почему не стоит просто писать `sum += number` и `count++` внутри параллельного цикла?
```spoiler
Потому что несколько потоков могут одновременно прочитать и изменить одну переменную. Возникает состояние гонки, и часть обновлений может потеряться.
```
В нашем решении:
- у каждой рабочей части цикла есть локальные `LocalSum` и `LocalCount`;
- локальные результаты накапливаются без постоянной синхронизации;
- после завершения локальной работы результаты объединяются через `Interlocked.Add`.

`Interlocked` обеспечивает атомарное добавление к общим переменным.

### `BenchmarkRunner.cs`
```cs
using System.Diagnostics;

namespace ParallelComputingLab;
// Класс проводит измерения и выводит медианное время.
public static class BenchmarkRunner
{
    private const int MeasurementCount = 5;

    public static void Run(int[] numbers)
    {
        ArgumentNullException.ThrowIfNull(numbers);

        Console.WriteLine();
        Console.WriteLine($"Размер массива: {numbers.Length:N0}");

        // Прогрев обеих реализаций.
        Calculator.CalculateSequential(numbers);
        Calculator.CalculateParallel(numbers);

        var sequentialTimes = new List<double>();
        var parallelTimes = new List<double>();

        CalculationResult? expectedResult = null;

        for (int i = 0; i < MeasurementCount; i++)
        {
            var sequential = Measure(
                () => Calculator.CalculateSequential(numbers));

            var parallel = Measure(
                () => Calculator.CalculateParallel(numbers));

            expectedResult ??= sequential.Result;

            if (sequential.Result != parallel.Result)
            {
                throw new InvalidOperationException(
                    "Последовательный и параллельный результаты не совпадают.");
            }

            sequentialTimes.Add(sequential.ElapsedMilliseconds);
            parallelTimes.Add(parallel.ElapsedMilliseconds);
        }

        Console.WriteLine(
            $"Сумма:           {expectedResult!.Sum:N0}");
        Console.WriteLine(
            $"Количество:      {expectedResult.Count:N0}");
        Console.WriteLine(
            $"Последовательно: {Median(sequentialTimes):F3} мс");
        Console.WriteLine(
            $"Параллельно:     {Median(parallelTimes):F3} мс");
    }

    public static (CalculationResult Result, double ElapsedMilliseconds)
        Measure(Func<CalculationResult> action)
    {
        var stopwatch = Stopwatch.StartNew();
        CalculationResult result = action();
        stopwatch.Stop();
        return (result, stopwatch.Elapsed.TotalMilliseconds);
    }

    private static double Median(List<double> values)
    {
        double[] sorted = values.OrderBy(x => x).ToArray();
        int middle = sorted.Length / 2;
        if (sorted.Length % 2 == 1)
        {
            return sorted[middle];
        }
        return (sorted[middle - 1] + sorted[middle]) / 2;
    }
}
```

Главный вывод занятия: параллелизм — не автоматический способ ускорить любую программу. Сначала нужно обеспечить корректность вычислений, затем измерить производительность и только после этого принимать решение о распараллеливании.

Задача: провести собственное исследование производительности параллельных вычислений.

1. Выбрать два размера массива: `100_000` и `5_000_000`.
2. Для каждого размера провести пять измерений.
3. Сравнить последовательный алгоритм и параллельный алгоритм с параметрами `1`, `2`, `4` и `-1`.
4. Проверить совпадение результатов.
5. Заполнить таблицу.
6. Написать вывод объёмом 5–7 предложений.

Шаблон таблицы:

|Размер|Вариант|Измерение 1|2|3|4|5|Медиана|
|---|---|---|---|---|---|---|---|
|100 000|Sequential|||||||
|100 000|Degree 1|||||||
|100 000|Degree 2|||||||
|100 000|Degree 4|||||||
|100 000|Default|||||||
|5 000 000|Sequential|||||||
|5 000 000|Degree 1|||||||
|5 000 000|Degree 2|||||||
|5 000 000|Degree 4|||||||
|5 000 000|Default|||||||

В выводе ответить:
- На каком размере массива параллельный вариант стал быстрее?
- Какое ограничение степени параллелизма оказалось наиболее эффективным?
- Всегда ли увеличение `MaxDegreeOfParallelism` ускоряло вычисления?
- Почему результаты разных запусков могут отличаться?
- В каких случаях лучше оставить последовательную реализацию?

Дополнительное задание: реализовать тот же алгоритм через `Parallel.ForEach` и сравнить его с `Parallel.For`.
