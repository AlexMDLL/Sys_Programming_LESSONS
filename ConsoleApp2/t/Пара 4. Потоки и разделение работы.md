Переходим к потокам внутри одного процесса: будем выполнять работу параллельно, наблюдать за порядком выполнения и исследовать проблему общего изменяемого состояния.

# Введение

Представим систему обработки заказов. Каждый заказ требует вычислений, например расчёта стоимости, проверки скидок и формирования итоговой суммы.

Можно обработать все заказы по очереди:

```
Заказ 1 → Заказ 2 → Заказ 3 → Заказ 4
```

А можно разделить работу между несколькими потоками:

```
Поток 1: Заказ 1 → Заказ 3
Поток 2: Заказ 2 → Заказ 4
```

Это не означает, что второй вариант обязательно окажется быстрее. Результат зависит от характера работы, количества потоков, доступных ядер процессора и накладных расходов на создание и синхронизацию потоков.

Вопрос студентам: если мы запустим четыре потока, гарантирует ли это, что они выполнятся одновременно и завершатся в том порядке, в котором были запущены?
```spoiler
нет. Планировщик операционной системы определяет, когда и сколько времени каждый поток получает на выполнение. На многоядерном процессоре потоки могут исполняться параллельно, но порядок не гарантируется.
```

Связь с предыдущим занятием: процесс запускает отдельную программу, а потоки позволяют разделить выполнение работы внутри одного процесса.

# Теория

## Процесс, поток и Task

Процесс - выполняющийся экземпляр программы со своим адресным пространством и системными ресурсами.

Поток   -  последовательность выполнения инструкций внутри процесса. Потоки одного процесса могут обращаться к общим объектам в памяти.

`Task` - объект .NET, представляющий асинхронную операцию или единицу работы. `Task` не равен потоку: задача может выполняться на потоке пула, на другом потоке или завершиться без выделения отдельного потока, например при асинхронном ожидании ввода-вывода.

В этом занятии мы используем именно `Thread`, чтобы увидеть жизненный цикл потоков и научиться работать с `Join()`.

```cs
using System;
using System.Threading;

Thread thread = new(() =>
{
    Console.WriteLine("Работа выполняется в отдельном потоке");
});

thread.Start();
thread.Join();

Console.WriteLine("Работа завершена");
```

Что произойдёт, если убрать `Join()`?

Главный поток не будет ждать завершения созданного потока в этой точке и сможет вывести сообщение раньше, чем завершится работа внутри него.

## Thread и Join

`Thread` позволяет создать отдельный поток выполнения.

Основные операции:

- `Start()` — запускает поток;
- `Join()` — блокирует вызывающий поток до завершения указанного потока;
- `IsAlive` — показывает, выполняется ли поток в данный момент;
- `ManagedThreadId` — идентификатор потока в управляемой среде .NET.

Пример:

```cs
Thread worker = new(() =>
{
    Console.WriteLine(
        $"ID потока: {Environment.CurrentManagedThreadId}"
    );
});

worker.Start();
worker.Join();
```

`Join()` — не способ синхронизировать доступ к общим данным. Он нужен для ожидания завершения потока. Если несколько потоков одновременно изменяют один объект, одного `Join()` недостаточно, чтобы предотвратить гонку данных.

Что произойдёт, если вызвать `Start()` у одного и того же экземпляра `Thread` дважды?
```spoiler
Повторный запуск одного экземпляра `Thread` не допускается: будет выброшено `ThreadStateException`.
```
## Жизненный цикл потока

В упрощённом виде жизненный цикл выглядит так:

1. Создание объекта `Thread`.
2. Запуск через `Start()`.
3. Выполнение делегата.
4. Завершение выполнения.

После завершения поток нельзя запустить повторно через тот же экземпляр `Thread`.

Пример наблюдения за состоянием:

```cs
Thread worker = new(() =>
{
    Console.WriteLine("Поток работает");
});

Console.WriteLine(worker.ThreadState);

worker.Start();
worker.Join();

Console.WriteLine(worker.ThreadState);
```

Состояние `Thread` может содержать несколько флагов, поэтому в реальных программах не стоит строить сложную логику только на сравнении `ThreadState` с одним конкретным значением.

Что произойдёт, если главный поток завершит свою работу раньше созданного потока?
```spoiler
Обычный фоновый поток `Thread` не завершает автоматически свою работу только потому, что главный поток дошёл до конца `Main`. При этом у фоновых потоков иные правила завершения процесса.
```
## Общее состояние и гонка данных

Потоки внутри одного процесса могут обращаться к одной переменной. Но если несколько потоков одновременно изменяют её без синхронизации, итог может оказаться непредсказуемым.

Рассмотрим:

```
int counter = 0;

Thread worker = new(() =>
{
    counter++;
});
```

Операция `counter++` не является одной неделимой операцией. Она включает чтение значения, вычисление нового значения и запись результата.

Если два потока одновременно прочитают `0`, каждый может вычислить `1` и записать его. Тогда после двух инкрементов счётчик окажется равен `1`, хотя ожидалось `2`.

Такое явление называют гонкой данных в бытовом контексте, а ситуацию, в которой результат зависит от порядка конкурентных операций - race condition. В терминологии C# гонка данных возникает, когда несколько потоков обращаются к одной памяти одновременно, а необходимые отношения синхронизации отсутствуют.

Для простого счётчика можно использовать `Interlocked.Increment()`:

```
Interlocked.Increment(ref counter);
```

Метод атомарно увеличивает значение и возвращает новое значение.

Что произойдёт, если заменить `counter++` на `Interlocked.Increment(ref counter)`?
```spoiler
Потоки продолжат выполнять работу конкурентно, но каждый инкремент счётчика станет атомарным, и итоговое число завершённых операций будет корректным.
```
# Demo

Два потока могут выводить сообщения в разном порядке.

```cs
using System;
using System.Threading;

Thread first = new(() =>
{
    for (int i = 1; i <= 5; i++)
    {
        Console.WriteLine(
            $"Поток A: {i}, ID={Environment.CurrentManagedThreadId}"
        );
        Thread.Sleep(10);
    }
});

Thread second = new(() =>
{
    for (int i = 1; i <= 5; i++)
    {
        Console.WriteLine(
            $"Поток B: {i}, ID={Environment.CurrentManagedThreadId}"
        );
        Thread.Sleep(10);
    }
});

first.Start();
second.Start();

first.Join();
second.Join();

Console.WriteLine("Оба потока завершены.");
```

`Thread.Sleep(10)` здесь используется только для наглядности, чтобы увеличить вероятность перемешивания вывода. Это не гарантирует конкретный порядок и не является способом синхронизации.

- сообщения потоков могут перемешиваться;
- идентификаторы потоков помогают увидеть, что работа выполняется в разных потоках;
- `Join()` гарантирует, что сообщение «Оба потока завершены» появится после завершения обоих потоков.
