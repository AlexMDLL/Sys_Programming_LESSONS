# П2

Цель: увидеть, что совместный доступ к переменной может привести к неверному результату, а затем исправить проблему атомарной операцией.

### Постановка задачи

Допустим, каждый обработанный заказ увеличивает общий счётчик:

```cs
completedOrders++;
```

Если несколько потоков выполняют эту строку одновременно, результат может оказаться меньше ожидаемого.

Вам нужно:

1. добавить общий счётчик в проект первой работы;
2. увеличивать его после обработки заказа;
3. запустить много операций;
4. попытаться воспроизвести неверный итог;
5. исправить счётчик через `Interlocked.Increment()`.

### Исправление

Замените:

```cs
completedOrders++;
```

на:

```cs
Interlocked.Increment(ref completedOrders);
```

Ожидаемое значение:

```
Ожидалось: 800000
Получено: 800000
```

Важное замечание: обычный инкремент не обязан давать неправильный результат в каждом запуске. Гонка данных зависит от расписания потоков и условий выполнения. Если ошибка не проявилась, увеличьте количество инкрементов и повторите тест.

Не нужно добавлять искусственные задержки между чтением и записью счётчика: они не превращают эксперимент в доказательство, а лишь меняют вероятность проявления ошибки.

### Вопрос на понимание

Почему `Join()` не исправляет счётчик?

Потому что `Join()` только заставляет главный поток дождаться завершения другого потока. Он не делает атомарными операции, которые выполняются одновременно внутри рабочих потоков.

`Interlocked.Increment()` решает именно проблему атомарного изменения целого числа. Для более сложного общего состояния может понадобиться `lock` или другой подход к синхронизации.
