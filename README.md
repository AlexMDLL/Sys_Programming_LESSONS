# Пара 11. Параллельные вычисления — стартовый проект

Скелет лабораторной работы к занятию «Параллельные вычисления»:
один и тот же массив обрабатывается последовательно и параллельно,
результаты сравниваются, время измеряется несколько раз и берётся медиана.

## Структура

```
ParallelComputingLab/
├── ParallelComputingLab.sln
├── ParallelComputingLab/
│   ├── Program.cs              — точка входа, наборы размеров массива
│   ├── DataGenerator.cs        — генератор массива с фиксированным seed
│   ├── CalculationResult.cs    — результат: сумма и количество
│   ├── Calculator.cs           — TODO: последовательная и параллельная обработка
│   └── BenchmarkRunner.cs      — измерения, медиана, сравнение степени параллелизма
├── ParallelComputingLab.Tests/
│   └── CalculatorTests.cs      — xUnit-тесты контрольных сценариев
└── t/
    └── Пара 11. Параллельные вычисления.md — текст занятия
```

Запуск:

```
dotnet run --project ParallelComputingLab            # всё: проверки + бенчмарки
dotnet run --project ParallelComputingLab -- checks  # контрольные сценарии П1
dotnet run --project ParallelComputingLab -- bench   # измерения П2
dotnet test
```

Результаты двух прогонов измерений — в `RESULTS.md`.

## П1. Одинаковый результат двумя способами

Обработать массив двумя способами:
1) последовательно через `foreach`;
2) параллельно через `Parallel.For`.

Для каждого способа вычислить сумму и количество чисел, кратных 7.

Проверка: контрольные сценарии (последовательная и параллельная реализации
должны давать одинаковый результат).

| Входные данные      | Ожидаемая сумма | Количество |
| ------------------- | --------------- | ---------- |
| `{ 7, 14, 20, 21 }` | 42              | 3          |
| `{ 1, 2, 3, 4 }`    | 0               | 0          |
| `{ }`               | 0               | 0          |
| `{ 7, 7, 7 }`       | 21              | 3          |

Задания:

1. Измените условие отбора: вместо чисел, делящихся на 7, выбирайте числа, делящиеся на 13.
2. Добавьте вычисление максимального подходящего элемента.
3. Проверьте массив, состоящий из одного элемента.
4. Проверьте пустой массив.
5. Попробуйте передать `null` и объясните, какое исключение должно возникнуть.
6. Запустите `CalculateParallelWrong` на массиве из нескольких миллионов элементов.
   Сравните его результат с правильным.
7. Исправьте `CalculateParallelWrong`, не меняя названия метода, через локальное
   состояние `Parallel.For`.

Критерий завершения: последовательная и параллельная реализации возвращают
одинаковые сумму и количество на всех контрольных сценариях.

## П2. Влияние степени параллелизма

`BenchmarkRunner.CompareParallelism` измеряет время для `MaxDegreeOfParallelism`
= 1, 2, 4 и -1 (по умолчанию).

Задания:

1. Добавьте размер массива 10 000 000.
2. Добавьте степень параллелизма 3.
3. Измените количество измерений с 5 на 10.
4. Добавьте в таблицу ускорение: время последовательной обработки / время параллельной.
5. Определите, на каком размере массива параллельная обработка стала быстрее.
6. Определите, какое значение `MaxDegreeOfParallelism` показало лучший результат.
7. Повторите эксперимент после перезапуска программы, сравните результаты.
8. Объясните в коде комментарием, почему `MaxDegreeOfParallelism = 4` может быть хуже,
   чем `MaxDegreeOfParallelism = 2`.
9. Добавьте проверку совпадения результата для каждого измеряемого варианта.
10. Сделайте вывод: всегда ли параллельная обработка быстрее последовательной?

Таблица для заполнения:

| Размер массива | Последовательно | Degree = 1 | Degree = 2 | Degree = 4 | Default |

| 10 000         |                 |            |            |            |         |

| 1 000 000      |                 |            |            |            |         |
